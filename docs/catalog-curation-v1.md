기준: [기획서 v3.2](<../AI 스케치 게임 서비스 기획서 v3.2.md>) §9.1("동의어 표기와 카테고리 중복·유사성은 목록 관리 단계에서 정리한다"), [라벨 검토](quickdraw-label-review.md), [속성 사전 v3](attribute-dictionary.md). 작성일: 2026-09-23.

결과 파일: [catalog-curation-v1.json](../config/model/catalog-curation-v1.json). 현재 버전은 `catalog-curation-v1.2`(2026-10-06)이며 아직 초안이다. v1.1에 학습을 마친 인식 모델의 결과를 반영했다(7절). 원본 카탈로그 `labels.json`과 모델 클래스 순서는 바꾸지 않는다.

## 정답에서만 제외하는 항목

기존 라벨 검토는 도형·기호·추상 활동 13개를 정답 제외로 제안했다(`exclude_proposed`). 이 중 별 모양과 웃는 얼굴 기호는 정답 후보로 다시 넣는다. 나머지 11개는 그대로 정답에서 제외한다. 제외된 11개도 점수는 계산한다. 사용자가 그렸을 때 인식하고 유사도를 보여주되 오늘의 정답으로만 내지 않는다.

| 구분 | 카테고리 | 이유 |
|---|---|---|
| 정답 후보로 되돌림 | 별 모양 `star`, 웃는 얼굴 기호 `smiley_face` | 누구나 같은 모양으로 알아보고 그리기 쉬운 대표 기호다. 사용자 결정(2026-09-23). |
| 정답 제외 유지 | 원, 육각형, 팔각형, 정사각형, 삼각형, 직선, 구불구불한 선, 지그재그 | 구체적인 대상이 아닌 기하 도형이다 |
| 정답 제외 유지 | 동물의 이동, 위장, 요가 | 대상이 아닌 동작·추상 개념이다 |
| 정답 제외 (v1.2) | 마커펜, 연못, 수영장, 곰, 정원 호스, 항공모함, 아이스박스 | 인식 모델로 그림 한 장 성공률이 0.3~4.2%이고 통합해도 나아지지 않는다(7절). 사용자 결정(2026-10-06). |

원본 `labels.json`의 `daily_status`는 바꾸지 않았다. 되돌린 두 항목과 v1.2에서 뺀 7개는 정리 파일의 `daily_overrides`에 기록했다.

## 2. 판단 기준

카테고리 쌍은 아래 순서로 판단했다.

| 기준 | 처리 | 예 |
|---|---|---|
| **같은 개념·하위 종류** (`same_or_subtype`) | 대표 개념으로 인정하는 규칙 초안 유지 | 머그잔→컵 |
| **부분을 전체로 인정** (`part_as_whole`) | 게임 규칙 초안으로 유지, 출시 전 검증 | 발가락→발, 무릎→다리 |
| **별개 개념의 구분 불가 주장** (`no_sketch_difference`) | 통합 보류, 각 후보 유지 | 블랙베리–블루베리, 여권–책 |
| **인식 모델이 서로 많이 헷갈림** (`model_confusion`, v1.2) | 사용자 결정으로 통합, 서로의 그림을 정답으로 인정 | 첼로→바이올린, 허리케인→토네이도 |
| **넓은 상위 개념이 여러 개별 카테고리와 겹침** (`broad_parent`) | 점수·정답 제외, 인식 후보와 확률은 유지 | 새 |
| 개념이 다르고 그림에서 구분되는 특징이 있음 | 둘 다 유지한다 | 사자–호랑이, 노트북–컴퓨터 |

대표는 다음 순서로 골랐다.

1. 더 일반적이고 한국어로 익숙한 이름 (컵, 케이크, 시계)
2. 전체 개념 (발, 팔, 다리)
통합은 하위 종류·부분 그림도 대표 정답으로 인정하겠다는 규칙이다. 태그 유사도만으로는 이 규칙을 승인하지 않는다. v1.2의 `model_confusion` 통합은 모델 혼동 수치와 사용자 결정을 함께 근거로 삼았다.

태그 유사도가 높다는 것만으로 합치지 않는다. v3 태그는 비슷한 대상의 점수가 가깝게 나오도록 일부러 공유하게 만들었기 때문이다. 예를 들어 사자–호랑이(0.89)는 가까운 점수가 나와야 하는 별개 대상이다.

근거 자료:

- **태그 유사도**: [속성 사전 v3](../data/attributes/draft-v3/dictionary.json)에서 분류·형태·기능 축별 태그 코사인의 평균. 두 대상 모두 태그가 있는 축만 쓴다.
- **그림 표본**: [Quick Draw 미리보기](../data/quickdraw/previews/index.html)의 라벨별 20장
- **기존 라벨 검토**의 우선 검토 목록

v1.1까지는 인식 모델의 혼동 행렬이 근거에 없었다. v1.2는 epoch 20 모델의 검증 결과를 더했다(7절).

## 3. 적용 방식

| 영역 | 처리 |
|---|---|
| 모델 출력 | 345개 logits 전체에 온도 보정·softmax를 적용한다. 원본 확률을 `service_id`별로 합산한 331개 후보(v1.2)에서 Top-3를 뽑는다. `bird`도 유지하고 마스킹·재정규화하지 않는다. |
| 제출 요청 | Top-3의 `categoryId`는 매핑 후 후보 ID다. 통합된 원본 ID는 대표 ID로 보내며 미지원 `bird`는 그대로 보낸다. p는 전체 확률 질량을 유지한 합산 값이다. |
| 미지원 후보 | Top-3에 `bird` 등 점수 미지원 후보가 하나라도 있으면 `deferred/unsupported_candidate`. 나머지만 골라 점수를 내지 않는다. |
| 동점 순서 | 후보에 합산되는 원본 `class_index` 중 최솟값을 `candidate_index`로 삼고, 같은 p일 때 이 값의 오름차순으로 정렬한다. |
| 점수표 | 대표 카테고리만 점수를 만든다. 통합된 원본의 v3 속성 레코드는 보존하되 점수에 쓰지 않는다. |
| 데일리 정답 | 대표 카테고리만 후보가 된다. 예를 들어 정답이 컵일 때 머그잔을 그려도 확률이 컵으로 합산되므로 성공할 수 있다. |
| 재학습 | 현재 학습 라벨 345개를 유지한다. 통합·정답 제외는 브라우저 합산과 점수표만 바꾸므로 재학습이 필요 없다. 출력 라벨 변경은 별도 모델·카탈로그 버전과 재평가가 필요하다. |
| 버전 | 이 초안을 선택하는 릴리스의 `catalogVersion`은 `catalog-curation-v1.2`이다(`model-dev-e20-v2`부터). 공개 manifest에 원본 순서·매핑·후보 순서·매핑 해시를 함께 고정하며 진행 중인 문제의 매핑은 바꾸지 않는다. v1.1로 만든 릴리스는 그대로 남는다. |
| 바꿀 때 | 버전을 올리고 `counts`와 `tests/test_catalog_curation.py`를 맞춘다 → 점수표 새 버전(`config/scoring/scoring.json`의 `version`·`output_dir`) → 새 릴리스 → 안 열린 문제 배정. 이미 배정된 문제의 정답이 빠지면 열리기 전에 `set-answer`로 바꾼다. |

예를 들어 원본 확률이 `bird=.98, owl=.018, duck=.001, parrot=.001`이면 `owl`은 여전히 `.018`이다. `bird`가 Top-1이므로 보류한다. `bird`를 지운 뒤 `owl=.9`로 만드는 방식은 사용하지 않는다. `q=p/sum(top3.p)`는 지원·확신도 검사를 통과한 뒤 유사도 혼합에만 사용한다.

확률 합산은 후보 수와 확신도 분포를 바꾸므로 보류·성공 임계값, 보정 품질, 혼동 행렬을 **매핑 적용 후 기준으로도** 평가한다. 원본 345개 평가 결과도 별도로 남긴다.

## 6. 한계와 다음 확인

- v1.1의 근거는 태그·그림 표본·기존 검토였다. v1.2에서 모델 혼동으로 통합 보류 쌍과 어려운 정답을 정리했다(7절). 남은 확인:
  - 태그는 다르지만 그림이 비슷한 쌍 (예: 프라이팬–테니스 라켓)
  - 5절에서 유지한 쌍 중 실제로 구분되지 않는 쌍. 모델 기준으로는 기타→바이올린 36%(첼로 통합 뒤), 승합차→버스 24%, 팔각형→육각형 21%가 크다.
  - 실제 그림판 그림에서도 같은 결과인지(지금 근거는 Quick Draw 그림뿐)
- 태그 유사도는 태그 작성 방식에 좌우된다. 무릎–다리의 통합은 구분 불가 판정이 아닌 부분 정답 인정 초안이다.
- 컵류·케이크·시계의 대표 처리와 새의 보류 방식을 정했다. 남은 통합 보류 3쌍과 부분 정답 인정 규칙은 게임 규칙 검증 대상으로 남긴다. 그 밖에 남은 라벨 검토:
  - `fish`
  - `diamond`, `stitches`, `fan`, `spreadsheet`
  - 고유 명소·작품 3개
- 이 정리는 정답·점수 목록을 줄이는 것이다. 모델 학습 데이터를 지우는 것이 아니다.

## 7. v1.2 변경 (2026-10-06, 인식 모델 반영)

근거: epoch 20 모델(`mobilenet_v3_small-20261001-093849-e20`, T 1.093)을 `qd-10k-64-v1` 검증 분할 344,327장에 돌려, 성공 기준 p1 ≥ 0.85에서 데일리 정답별 그림 한 장 성공률을 쟀다. 테스트 분할은 쓰지 않았다. 수치는 정리 파일의 `model_evidence`에 있다.

어려운 정답은 원인이 둘이었다.

- **헷갈리는 짝 때문**: 1위로 맞혀도 짝과 확률을 나눠 가져 p1이 기준에 못 미친다. 토네이도는 1위 정확도가 67%인데 성공률은 1%였다. 이런 짝 4개를 통합했다(4절).
- **그 자체로 어려움**: 1위 정확도부터 22~40%이고 통합할 짝도 없다. 마커펜(0.3%)·연못(0.9%)·곰(2.2%)·정원 호스(2.3%)·항공모함(2.5%)·아이스박스(4.1%)·수영장(4.2%)을 정답에서만 뺐다. 인식 후보와 점수에는 남는다.

결과:

| | v1.1 | v1.2 |
|---|---:|---:|
| 게임 후보 top-1 (선택용 절반) | 71.1% | 71.6% |
| 데일리 정답 중 성공률 5% 미만 (선택용 절반) | 8개 | 0개 |
| 데일리 정답 중 성공률 30% 미만 (선택용 절반) | 92개 | 79개 |
| 전체 잘못된 성공 / 그림 한 장 성공, p1 ≥ 0.85 (보정용 절반) | 4.7% / 42.1% | 4.7% / 42.9% |

통합해도 잘못된 성공은 그대로라 성공 기준 0.85를 유지한다.

검토한 뒤 통합하지 않은 것: 블루베리+블랙베리, 책+여권, 세탁기+식기세척기(통합해도 효과가 없거나 한쪽이 나빠짐), 마커펜+크레용, 연못+수영장(통합해도 7~8%), 기타(바이올린·첼로와 셋을 합치면 74%지만 별개 악기라 사용자 결정으로 유지), 육각형+팔각형(정답 제외 도형이라 영향 없음). 성공률 5~10%인 드래곤·껍질콩·블랙베리·휴대전화 등 10개는 실제 플레이 정답률(`python -m app.cli metrics`)을 보고 다시 정한다.
