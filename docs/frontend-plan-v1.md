# 프론트 화면·핵심 기능 계획 v1

기준: [기획서 v3.2](<../AI 스케치 게임 서비스 기획서 v3.2.md>), [서비스 아키텍처](service-architecture-v1.md), [핵심 파일 계획](core-file-plan-v1.md). 작성일: 2026-09-22. 화면 구현 전 계획이다.

## 1. 화면 방향

**상단에서 그림을 제출하고, 바로 아래에서 이전 그림과 유사도를 비교하며, 하단에서 Q&A를 읽는 단일 페이지**로 구성한다. 모바일과 데스크톱을 초기 지원 범위로 둔다. 데스크톱에서도 같은 세로 순서를 유지한다.

[꼬맨틀 공개 페이지](https://semantle-ko.newsjel.ly/)에서 확인한 문제 안내·입력 영역·하단 질문과 답변의 흐름을 참고한다. 본 서비스의 그림판 크기, 기록 배치, 반응형 수치는 아래 자체 설계안이다. 꼬맨틀의 실제 모바일 동작을 검증한 결과로 간주하지 않는다.

사용자가 요청한 방향은 상단 그림판, 하단 썸네일+점수 누적 기록, 그 아래 설명글이다. 최대 폭·그림판 크기·기록 표시 개수 등은 구현 시 실제 화면으로 확인할 권장 초깃값이다.

그림 게임에서는 같은 대상을 수정해도 AI의 해석이 달라질 수 있다. 제출 당시 그림을 점수와 함께 남겨야 사용자가 변화를 비교할 수 있다. 그림은 제출 후에도 유지해 바로 수정할 수 있게 한다.

## 2. 페이지 구조

```text
┌─────────────────────────────────────┐
│ 서비스명                   이용 방법 │
│ 오늘의 문제 #번호 · 날짜              │
│ 오늘의 정답을 그림으로 찾아보세요.    │
├─────────────────────────────────────┤
│         정사각형 그림판              │
│                                     │
│                                     │
│                                     │
│   [되돌리기] [지우기] [제출하기]      │
│   준비 상태 / 마지막 제출 결과       │
│   학습용 그림 제공 선택              │
├─────────────────────────────────────┤
│ 성공 결과 — 성공한 경우에만 표시     │
├─────────────────────────────────────┤
│ 제출 기록       시도 N회 · 최고 점수 │
│ 번호      제출한 그림        유사도  │
│  N        [썸네일]           점수    │
│  N-1      [썸네일]           점수    │
│  …                                  │
│         [이전 기록 더 보기]          │
├─────────────────────────────────────┤
│ 질문과 답변                         │
│ Q. 어떤 게임인가요?                 │
│ A. …                                │
│ Q. 점수는 무엇을 뜻하나요?           │
│ A. …                                │
├─────────────────────────────────────┤
│ 데이터 출처 · 서비스 안내            │
└─────────────────────────────────────┘
```

상단의 `이용 방법`은 페이지 아래 Q&A로 이동하는 링크다. 그림판 다음에 결과·기록을 배치하고 설명글은 마지막에 둔다. 제출 결과를 확인하기 위해 별도 화면으로 이동하지 않는다.

초기에는 밝은 배경, 어두운 글자와 선, 얇은 구분선, 하나의 강조색을 사용한다. 그림판은 흰 배경에 검은 선으로 표시한다. 학습 텐서의 극성은 전처리 명세에 맞춰 변환하며 화면 색상과 구분한다. 점수에 퍼센트 기호를 붙이거나 임의의 온도 구간·진행 막대를 만들지 않는다.

## 3. 모바일·데스크톱 배치

| 항목 | 모바일 | 태블릿·데스크톱 |
|---|---|---|
| 페이지 | 한 열, 좌우 여백 16px 권장 | 가운데 한 열, 본문 최대 폭 720px 권장 |
| 그림판 | 가용 폭 안의 정사각형, 최대 360px 권장 | 정사각형 최대 400px 권장 |
| 편집·제출 버튼 | 그림판 아래 세 버튼. 좁으면 제출 버튼을 다음 줄 전체 폭으로 배치 | 그림판 아래 한 줄 |
| 기록 | 번호·썸네일·점수 세 열 유지 | 같은 세 열을 넉넉한 간격으로 배치 |
| 썸네일 | 56~64px 정사각형 권장 | 64~72px 정사각형 권장 |
| 설명 | 질문과 답을 줄바꿈해 모두 노출 | 동일한 본문 구성 |

768px을 기본 배치 전환점으로 검토하되 기기 이름보다 실제 가용 폭에 맞춘다. 320px 폭에서도 가로 스크롤 없이 버튼·점수·설명이 보여야 한다. 작은 가로 화면에서는 높이에 맞춰 그림판을 줄이고 필요하면 페이지를 스크롤한다. 모든 내용을 한 화면 높이에 억지로 맞추지 않는다.

터치 영역은 44px 이상을 설계 목표로 잡는다. 그림판 내부 터치는 그리기에 사용하고 바깥 영역은 페이지 스크롤에 사용한다. 페이지 전체의 확대·스크롤을 막지 않는다. 마우스·터치·펜 입력을 지원하고 보조 터치가 새로운 획으로 섞이지 않게 한다.

화면 회전·창 크기 변경 시 논리 좌표의 획을 다시 그려 비율과 내용을 보존한다. 표시 해상도와 모델 입력 해상도를 분리해 같은 그림이 화면 폭 때문에 다른 입력이 되지 않도록 검증한다. 고해상도 화면에서도 선과 썸네일이 흐려지지 않게 한다.

획 원본 규격과 모델 입력은 [모델 구조](model-architecture-v1.md)를 따른다. 좌표를 저장하는 것과 신경망에 이미지를 입력하는 것은 양립한다. 첫 후보는 좌표에서 렌더한 64×64 단색 입력이며, 기존 28×28 데이터 전처리와 버전을 구분한다. 모바일 브라우저 실행은 실제 기기 평가 후 확정한다.

## 4. 그림판과 제출

- 도구는 단색 펜, 마지막 획 되돌리기, 전체 지우기, 제출이다. `지우기`는 현재 그림만 비우며 기록은 유지한다.
- 모델 준비 중에는 준비 상태를 표시한다. 빈 그림·모델 미준비·제출 처리 중에는 제출 버튼을 비활성화하고 이유를 안내한다.
- 제출 순간의 획과 썸네일을 고정해 해당 제출 ID에 연결한다. 처리 중에는 중복 제출과 편집을 잠시 막는다.
- 결과가 오면 편집을 다시 허용한다. 성공 전에는 그림을 자동으로 지우지 않으며 바로 수정할 수 있다.
- 마지막 점수는 `마지막 제출 유사도`로 표시한다. 이후 수정하면 `그림이 수정됐어요. 제출하면 다시 확인할 수 있어요.`를 함께 표시한다. 지우기 후에는 그림판 근처의 점수를 비우고 기록은 보존한다.
- 실패 시 그림을 보존한다. 통신 결과가 불확실하면 기존 제출 ID·사본으로 확인/재시도하고, 결과 확인 전에는 새 제출을 시작하지 않는다. 새로고침 후에도 미완료 제출을 먼저 확인한다.

## 5. 제출 기록

### 추가와 표시 규칙

유효한 판정 결과가 서버에서 확정되면 **기록 맨 위에 한 행을 추가**한다. 기본 순서는 최신순이다. 화면에 보이는 번호는 서버의 시도 번호이며 클릭 횟수나 배열 길이로 계산하지 않는다.

| 열 | 표시 내용 |
|---|---|
| 번호 | 해당 문제에서 서버가 확정한 시도 번호 |
| 제출한 그림 | 제출 순간의 고정된 썸네일. 현재 그림판 수정과 독립 |
| 유사도 | 서버의 표시 점수. 판정 성공 여부와 별개 |

기록 위에 `시도 N회 · 최고 유사도 X`를 표시한다. 기록이 없으면 `아직 제출한 그림이 없어요.`를 표시하고 최고 점수는 `—`로 둔다. 음수 점수를 허용하는 표시 체계에서도 최고값을 임의로 0부터 시작하지 않는다.

최고 기록에는 `최고`, 성공한 행에는 `정답` 문구를 표시해 색상만으로 의미를 구분하지 않는다. 최고 기록이 같다면 최신 한 행에 표시하는 것을 권장한다. 비교는 서버 기준으로 처리하고 반올림된 문자열에서 최고값을 다시 추정하지 않는다. API 연결 시 최고 기록 식별값과 표시 자릿수를 함께 확정한다.

점수 범위·소수 자릿수는 기존 기획서대로 아직 미정이다. 프론트가 0~100으로 고정하거나 높은 점수를 정답으로 간주하지 않는다. 정답 여부는 서버 성공 결과를 따른다. AI 예측 단어·확신도·숨겨진 속성별 점수·혼합 순위는 기본 화면에 표시하지 않는다.

### 기록이 많아지는 경우

초기에는 최신 10개를 표시하고 `이전 기록 더 보기`로 10개씩 펼치는 방식을 권장한다. 기록 자체는 누적 보존한다. 긴 내부 스크롤 영역이나 자동 무한 스크롤을 만들지 않아 Q&A에 접근할 수 있게 한다.

신규 결과는 제출 버튼 근처에도 안내해 기록을 찾으러 이동할 필요를 줄인다. 이전 기록이나 Q&A를 읽는 중에는 강제로 화면 위치를 바꾸지 않는다. 기록 아래의 `그림판으로 돌아가기` 링크로 편집 영역에 돌아올 수 있게 한다. 초기에는 그림판 전체를 화면에 고정하지 않는다.

### 새 행과 시도 수를 추가하지 않는 경우

| 결과 | 화면 처리 |
|---|---|
| 빈 그림 | 제출하지 않고 그리기 안내 |
| 판정 보류 | `그림을 더 분명하게 그려주세요.` 등 원인에 맞는 안내. 점수·시도 번호 없음 |
| 동일 그림 재제출 | 기존 결과를 보여주고 해당 행 안내. 이미 있는 기록은 중복 추가하지 않음 |
| 통신·추론 실패 | 그림 유지, 오류와 재시도 제공. 임의의 0점 기록을 만들지 않음 |
| 학습용 업로드 실패 | 점수·성공·기록 유지, 수집 상태만 별도 안내 |

서버에서 확정됐지만 응답을 놓친 제출은 재시도로 복구하면 한 번만 기록한다. 로컬에 없던 확정 기록은 제출 ID로 합쳐서 표시한다. 판정 보류는 서버 로그로 관리하고 점수가 있는 제출 기록과 구분한다.

## 6. 성공·복원·학습용 제공

성공하면 그림판 아래에 정답 단어·성공한 그림·총 시도 수·최고 점수를 표시한다. 제출 기록과 Q&A는 계속 열람할 수 있다. 초기 화면은 성공한 문제의 추가 제출을 종료하는 기본안으로 두며 성공 후 자유 실험 모드는 후속 검토한다.

새로고침 시 서버에서 자신의 제출 결과를 확인하고 로컬 썸네일·진행 중 그림을 연결한다. 세션은 남았지만 로컬 그림이 없으면 `그림 미리보기 없음`으로 표시하고 서버 점수는 유지한다. 다른 기기 동기화나 브라우저 데이터 삭제 후 복원을 약속하지 않는다.

한국 시간 자정을 넘어도 진행하던 문제와 버전은 유지한다. 새 문제 안내를 표시하되 자동으로 캔버스와 기록을 교체하지 않는다.

학습용 그림 제공은 그림판 아래에 선택 사항으로 안내하고 기본 미선택으로 제안한다. 제출 버튼과 분리하고, 제공하지 않아도 플레이할 수 있게 한다. 동의·표본 선정 후에만 원본을 업로드한다. 초기 안내 문구는 `그림 인식 개선을 위해 제출한 그림을 학습용으로 제공할 수 있어요.`로 두고, 보관 기간·삭제 방법은 수집 정책 확정 후 실제 안내에 반영한다.

선택 변경은 별도 API로 처리하고 서버가 반환한 리비전을 보관한다. 오래된 제출의 재시도가 선택을 다시 켜지 않는다. 업로드에는 현재 그림판 대신 해당 제출의 고정 사본을 사용한다. 정확한 요청·응답과 상태는 [API 계약](api-contract-v1.md)을 따른다.

## 7. 하단 Q&A 초안

질문과 답을 일반 설명글로 모두 펼쳐 둔다. 게임을 처음 시작하기 전에 긴 안내를 반드시 읽도록 요구하지 않는다. 아래 내용은 본 서비스용 문안이며 서비스명·운영 정책 확정 시 맞춰 다듬는다.

### 어떤 게임인가요?

오늘의 정답을 그림으로 추측하는 게임이에요. 그림을 제출하면 정답과 얼마나 비슷한지 점수로 알려드려요. 이전 그림과 점수를 비교하며 정답에 가까워져 보세요.

### 무엇을 그리면 되나요?

사물이나 동물처럼 그림으로 표현할 수 있는 대상을 그려보세요. 서비스가 인식할 수 있는 대상 중에서 정답을 골라요. 세상의 모든 그림을 알아보는 것은 아니에요.

### 유사도 점수는 무엇인가요?

AI가 그림을 해석한 결과를 바탕으로 정답과의 관련성을 나타내는 점수예요. 그림 실력을 평가하는 점수나 정답일 확률은 아니에요. 숫자가 높을수록 정답과 더 가깝게 평가됐다는 뜻이에요.

### 점수가 높으면 정답인가요?

높은 유사도와 정답 판정은 달라요. 정답으로 판정되면 별도로 알려드리고 정답 단어를 공개해요.

### 그림을 조금 고쳤는데 점수가 많이 달라졌어요.

AI가 그림을 다른 대상으로 해석했을 수 있어요. 여러 대상을 한꺼번에 넣기보다 한 대상의 특징을 분명하게 그려보세요.

### 점수가 나오지 않는 경우도 있나요?

그림을 분명하게 인식하기 어렵거나 현재 지원하지 않는 대상으로 해석되면 판정을 보류할 수 있어요. 보류된 제출은 시도 횟수에 포함하지 않아요. 연결 오류가 나면 그림을 유지한 채 다시 시도할 수 있어요.

### 지우기를 누르면 기록도 없어지나요?

지우기는 현재 그림판만 비워요. 제출한 그림과 점수는 아래 기록에 남아요. 같은 그림을 다시 제출하거나 통신 오류로 재시도해도 횟수가 중복으로 늘어나지 않아요.

### 새 문제는 언제 나오나요?

매일 한국 시간 자정에 새 문제가 열려요. 풀고 있던 문제는 이어서 풀 수 있어요.

### 새로고침해도 이어 할 수 있나요?

같은 브라우저에서 진행한 기록을 이어 볼 수 있도록 저장해요. 브라우저 데이터를 지우거나 다른 기기로 접속하면 이전 기록이나 그림을 복원하지 못할 수 있어요.

### 제가 그린 그림이 학습에 사용되나요?

학습용 제공을 선택한 경우에만 제출한 그림 중 일부를 보관해 인식 개선에 활용할 수 있어요. 제공하지 않아도 게임을 할 수 있어요. 자세한 보관 기준은 선택 영역의 안내에서 확인할 수 있어요.

마지막 답변은 보관·삭제 안내가 실제로 준비된 뒤 수집 기능과 함께 공개한다. 브라우저의 플레이 기록 저장과 서버의 학습 원본 보관을 구분한다.

## 8. 핵심 파일에 반영할 책임

기존 폴더를 그대로 사용한다. 전체 목록은 [핵심 파일 계획](core-file-plan-v1.md)이 기준이며 이번 화면 계획으로 아래 책임을 구체화한다.

| 파일 (`frontend/src/` 기준) | 화면에서 맡는 일 |
|---|---|
| `features/game/GamePage.tsx` | 제목·문제 안내·그림판·조작 버튼·상태·수집 선택·성공·기록·Q&A를 순서대로 배치 |
| `features/drawing/DrawingCanvas.tsx` | 마우스·터치·펜 입력, 화면 크기 변경 시 획 보존, 편집 잠금 |
| `features/drawing/drawingState.ts` | 획·Undo·Reset·제출 후 수정 여부 |
| `features/drawing/drawingSnapshot.ts` | 제출 시 획·해시·썸네일 고정 |
| `features/game/useGame.ts` | 서버 기록과 로컬 그림 복원, 마지막 결과·성공·최고 기록 상태 |
| `features/game/submissionFlow.ts` | 한 번의 제출·실패·재시도·결과 반영. 중복 행/시도 증가 방지 |
| `features/game/SubmissionHistory.tsx` | 최신순 세 열 기록, 최고·정답 표시, 더 보기, 그림판 복귀 링크 |
| `features/game/ResultPanel.tsx` | 성공 후 정답·성공 그림·총 시도·최고 점수 |
| `features/game/GameFaq.tsx` | 하단 질문·답변과 이용 방법 앵커. 이번에 추가로 계획한 파일 |
| `features/game/game.css` | 한 열 레이아웃, 반응형 그림판·버튼·기록·Q&A 스타일. 이번에 추가로 계획한 파일 |
| `features/collection/CollectionConsent.tsx` | 선택 상태·보관 안내 연결·수집 오류 안내 |
| `shared/storage/gameStorage.ts` | 문제·제출 ID별 그림·썸네일·미완료 제출 보관, 누락/저장 실패 처리 |

추론·API·업로드의 파일 책임은 기존 계획을 유지한다. 작은 제목·기록 행·버튼별로 파일을 추가하지 않는다. `GameFaq`는 독립적인 설명 콘텐츠를 관리하고 `game.css`는 게임 화면 전용 스타일을 모은다. 다른 화면에서도 실제 재사용할 스타일만 `shared/styles`로 옮긴다.

## 9. 구현 순서와 확인 기준

1. 모의 데이터로 그림판·기록·Q&A의 한 페이지 배치와 모바일 폭을 확인한다. 개발용 모의 점수는 화면에 명시한다.
2. 실제 획 입력·Undo·Reset·고정 썸네일과 기록 누적을 연결한다.
3. API·브라우저 추론을 연결하고 보류·오류·중복·성공·복원을 확인한다.
4. 수집 선택과 업로드 상태를 연결하고 실제 모바일 기기에서 그리기·스크롤·응답 시간을 확인한다.

구현 완료 시 아래를 확인한다. 이번 단계에서는 화면·테스트 코드를 생성하지 않는다.

- 320/360/390/768/1440px 폭과 모바일 가로 방향에서 가로 넘침, 잘린 점수, 버튼 겹침이 없다.
- iOS Safari·Android Chrome·데스크톱 Chrome/Edge에서 입력과 WASM 추론을 확인한다. 지원 범위는 실제 검증 결과로 확정한다.
- 캔버스 밖에서는 스크롤이 되고 크기 변경 후에도 그림이 유지된다.
- 기록 0/1/10/50개, 긴 점수 문자열, 썸네일 누락에서도 배치와 더 보기가 동작한다.
- 정상 판정 한 번당 한 행, 보류·중복·오류에는 추가 시도 없음, 늦은 응답·재시도에도 중복 없음이 성립한다.
- 수정·Reset 후에도 이전 썸네일이 바뀌지 않고 마지막 결과와 편집 중 상태가 구분된다.
- 키보드로 버튼·링크에 접근하고 초점이 보인다. 결과 변경은 보조기기에 알리고 자동 초점 이동을 강요하지 않는다. 썸네일에는 `N번째 제출 그림` 같은 설명을 제공한다.
- 준비 중·실패·성공 문구와 최고 표시를 색상만으로 전달하지 않는다. 키보드만으로 자유롭게 그림을 입력하는 기능은 아직 설계하지 않았으므로 전체 게임의 접근성 완료를 주장하지 않는다.

기존 `submissionFlow.test.ts`, `game.spec.ts`, `preprocess.test.ts`에 관련 검증을 배치한다. 화면 계획만을 위해 별도 테스트 폴더를 추가하지 않는다.
