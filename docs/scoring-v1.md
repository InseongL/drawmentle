보류·성공 판정은 [판정 기준 v1](judging-criteria-v1.md)을 따른다. 이 문서는 점수만 다룬다.

설정: [scoring.json](../config/scoring/scoring.json) · 계산 함수: [similarity.py](../backend/app/modules/judging/similarity.py), [scorer.py](../backend/app/modules/judging/scorer.py) · 도구: [scripts/scoring](../scripts/scoring/)

## 1. 한눈에 보기

관계 점수 R(c, t)는 후보 c와 정답 t가 얼마나 가까운지를 0~1로 나타낸다. 점수 지원 카테고리 334개 사이의 R을 미리 계산해 점수표로 만든다. 제출 때는 이 표에서 값을 찾아 쓰기만 한다.

| 축 | 가중치 | 입력 | 비교 방법 |
|---|---:|---|---|
| 분류 | 0.25 | v3 분류 트리 태그(상위 분류 포함) | 희귀도 가중 코사인 |
| 형태 | 0.25 | v3 형태 태그 | 희귀도 가중 + 태그 계열 부분 점수(0.3) |
| 기능 | 0.20 | v3 기능 태그 | 형태와 같음 |
| 연상 | 0.30 | 영어 라벨의 fastText 단어 벡터 | 코사인 → 직선 보정 |

```
R(c, t) = Σ w_m · s_m(c, t) / Σ w_m        (두 대상 모두 값이 있는 축만)
R(t, t) = 1
혼합   = Σ q_i · R(c_i, t),  q_i = p_i / (p_1 + p_2 + p_3)
화면   = 100 × 혼합, 소수 둘째 자리 (반올림)
```

## 2. 비슷한 서비스와의 비교

2026-09-25에 각 서비스의 공개 설명을 확인했다.

| 서비스 | 점수 기준 | 보여 주는 것 |
|---|---|---|
| 꼬맨틀 | 단어 벡터(fastText, Common Crawl·위키백과)의 의미 유사도 | -100~+100 점수. 상위 1,000위 안이면 순위도 보여 준다. 1위·10위·1,000위 단어의 유사도를 기준값으로 알린다. |
| Semantle | word2vec 의미 거리 | 점수와 상위 1,000위 근접도 |
| Contexto | AI 유사도 순위 | 순위만 보여 준다(정답이 1위) |
| 카맨틀 | 미리 계산한 의미 벡터 거리 | 점수와 온도 표현 |
| Metazooa | 생물 분류 트리의 공통 조상 | 공유하는 분류 단계 |
| **이 서비스** | 속성 태그 3축과 이름 연상 1축을 합산하고, 모델 Top-3 확률로 혼합한다 | 유사도 점수(순위 공개는 미정) |

기획서 §3은 꼬맨틀의 단어 벡터 방식을 그대로 복제하지 않고 속성 비교와 결합하라고 한다. 그래서 단어 벡터는 네 축 중 하나(가중치 0.30)로만 쓴다. 분류·형태·기능 태그가 점수의 중심을 잡는다.

단어 게임과 다른 점은 두 가지다. 입력이 정확한 단어가 아니라 **모델의 인식 결과**라는 점, 그리고 후보가 수만 단어가 아니라 **334개**라는 점이다. 후보가 적어 태그만으로는 점수가 거칠게 나온다. 1·2장의 장치는 이 차이를 메우려는 것이다.

## 3. 규칙별 근거

### 3.1 희귀도 가중치

태그 무게는 `ln((N + 1) / (max(df, 2) + 1)) + 1`이다. N=334, df는 그 태그를 쓴 카테고리 수다.

`elongated`, `artifact`처럼 흔한 태그를 공유하는 것보다 `feline`, `siren_light`처럼 드문 태그를 공유하는 것이 더 가까운 관계다. 한 곳에만 쓰인 태그는 다른 대상과 겹칠 수 없으므로, df=2와 같은 무게로 상한을 둔다. 그래야 짝 없는 태그가 자기 벡터를 독차지하지 않는다.

### 3.2 태그 계열 부분 점수 (형태·기능)

비슷한 태그끼리는 0.3만큼 일치로 인정한다(soft cosine). 계열은 형태 26개, 기능 17개이며 설정 파일에 목록이 있다. 예를 들면 다음과 같다.

- 둥근 윤곽: 원·타원·돔·초승달·부푼 윤곽
- 다리: 두 다리·네 다리·여러 다리·바지 다리통
- 소리: 연주·소리 출력·녹음·방송 수신·듣기

분류는 트리 구조가 이미 단계별 점수를 주므로 계열을 쓰지 않는다. 계열 부분 점수를 0.2~0.5로 바꿔도 결과는 비슷했고, 0.3일 때 가까운 쌍의 순위가 가장 좋았다. `bending`은 작업 계열에 두면 팔–드릴 같은 연결이 생겨 이동 계열로 옮겼다.

### 3.3 연상 축 (단어 벡터)

태그가 잡지 못하는 **같은 장면·맥락 관계**를 더한다. 우산–비, 열쇠–문, 텐트–모닥불처럼 형태와 기능이 달라도 함께 떠올리는 관계다.

- **영어 라벨을 쓴다**: 한국어 이름은 한 글자이면서 뜻이 여럿인 것이 37개다(배·말·눈·성·원·비·강·달·산·못 등). 그래서 Quick Draw 원래 영어 라벨을 쓴다.
- **대체어 목록**: 영어에서 뜻이 섞이는 라벨은 대체어를 쓴다. 예: saw → handsaw, fan → fan + electric, hot dog → hotdog. 대체어로는 다른 카탈로그 라벨의 단어를 쓰지 않는다.
- **여러 단어 라벨**: 단어 벡터의 평균을 쓴다.
- **보정**: 334개 사이 모든 쌍의 코사인 분포에서 하위 10% 지점(0.084)을 0, 상위 0.5% 지점(0.531)을 1로 두고 직선으로 잇는다. 기준값은 점수표 manifest에 고정한다.
  - 0점 기준을 중앙값으로 두면 0점이 22%였다. 하위 10%로 낮춰 5%로 줄였다.
  - 더 낮추면 관계없는 쌍이 기본 점수를 받는 부작용이 커진다(3.5절 표).

### 3.4 결측·정답·혼합·표시

- **해당 없음 축**: 두 대상 중 하나라도 축이 known이 아니면 그 축을 빼고 남은 가중치로 나눈다. 기획서 §7.5의 기본안이다. 0점으로 처리해도 순위 차이는 작았다. 연상 축은 모든 대상에 있어 빠지지 않는다.
- **정답 자신**: R=1이다. 내부 순위에서 정답은 1위이고, 나머지는 R 내림차순으로 공동 순위를 쓴다(소수 여섯째 자리에서 비교).
- **Top-3 혼합**: 기획서 §7.4 그대로다. 미지원 후보(`bird`)가 있거나 p 합이 0이면 계산하지 않고 거부한다. 보류 판정은 `judge.py`의 몫이다.
- **화면 점수**: `100 × 혼합`을 소수 둘째 자리에서 반올림한 문자열을 서버가 만든다. 프론트는 다시 반올림하지 않는다.

### 3.5 비교 실험

점수 지원 334개로 계산했다.

- "가까운 쌍"은 속성 정책의 혼동 그룹 208쌍이다.
- "연상 쌍"은 태그로는 멀지만 함께 떠올리는 30쌍이다.
- 둘 다 설계를 비교하는 지표이지 통과 기준은 아니다.

| 방식 | 상위 20 중 서로 다른 점수 | 0점 비율 | 가까운 쌍 상위 10위 | 연상 쌍 상위 10위 |
|---|---:|---:|---:|---:|
| 태그 0/1 코사인, 3축 평균 | 54% | 49% | 90% | 50% |
| + 희귀도 가중치 | 86% | 49% | 89% | — |
| + 태그 계열 0.3 | 94% | 38% | 91% | 50% |
| + 연상 0.3 (0점 기준 중앙값) | 99% | 22% | 92% | 72% |
| **+ 연상 0.3 (0점 기준 하위 10%) — v1** | **99.6%** | **4.9%** | **93%** | **68%** |
| + 연상 0.3 (0점 기준 하위 1%) | 100% | 0% | 93% | 63% |

검토한 뒤 채택하지 않은 것:

- **축별 백분위 보정**: 기능 축은 95%가 0이라, 백분위로 바꾸면 드물게 겹친 경우가 지나치게 높아졌다. 가까운 쌍 상위 10위 비율이 90%에서 83%로 떨어졌다.
- **그림 복잡도(평균 획 수)**:
  - 사용자 그림의 획 수는 같은 카테고리 안에서도 편차가 크다. 카테고리가 설명하는 부분이 40%뿐이고, 일부러 획 수를 바꿔 정답의 복잡도를 떠볼 수 있다.
  - 카테고리 평균 획 수를 보조 축으로 넣으면 동점은 줄지만, 의미가 아니라 그리기 난이도라서 뺐다.
  - 데일리 난이도 조절·힌트 용도로는 다시 검토할 수 있다.

## 5. 만들기와 검사

```powershell
python scripts/scoring/extract_label_vectors.py   # 단어 벡터 필요 부분만 추출(네트워크 사용)
python scripts/scoring/build_score_table.py       # 점수표 + manifest 생성
python scripts/scoring/check_score_table.py       # 무결성 검사 + 검토 보고서
```

- 산출물은 `data/artifacts/scoring/`에 두며 Git으로 추적하지 않는다(정답 관계와 라이선스 데이터 포함).
- 검사는 다음을 확인한다. 하나라도 어긋나면 실패한다.
  - 입력·설정 해시, 카탈로그 정리와의 일치
  - 대칭성, 0~1 범위, 대각선 1
  - 축 합산 재현, 다시 만들었을 때 같은 결과
- 검사 통과가 점수의 납득 가능성을 보장하지는 않는다. 보고서의 "데일리 후보별 가까운 카테고리 10개"를 직접 읽는다.

## 6. 라이선스와 출처 표기

연상 축은 fastText `cc.en.300`(CC BY-SA 3.0)에서 뽑은 단어 벡터로 만든다. 출처: E. Grave, P. Bojanowski, P. Gupta, A. Joulin, T. Mikolov, *Learning Word Vectors for 157 Languages*, LREC 2018.

- 추출한 벡터와 점수표는 저장소에 올리지 않는다. 저장소에는 추출 규칙(설정)과 도구만 둔다.
- 서비스 화면에는 꼬맨틀처럼 사용한 단어 벡터의 출처를 표시한다.

## 7. 한계와 다음 단계

- 연상 축에는 단어 벡터 학습 데이터의 편향과 영어 다의어가 남는다. 예: bat은 대체어를 써도 단어 벡터만 보면 baseball bat이 가깝다. 태그 축 비중이 70%라 합산 순위에는 영향이 작지만, 보고서에서 계속 확인한다.
- 우산–비처럼 연상은 강하지만 합산 순위가 낮은 쌍이 있다. 가중치 조정은 플레이 테스트 후 판단한다.
- 아직 정하지 않은 것:
  - 인식 보류·성공 임계값(모델 필요, `judge.py`)
  - 순위 공개 여부
  - 꼬맨틀식 기준값 표시(정답별 1위·10위 점수)
  - 온도 표현
- 속성 사전·카탈로그 정리·설정이 바뀌면 점수표를 다시 만든다. 진행 중인 문제는 발행된 점수표 버전을 유지한다.
